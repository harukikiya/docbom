# DocBOM

**外部技術文書のための構成管理とロックファイル。**

DocBOM（Document Bill of Materials）は、データシート、リファレンスマニュアル、エラッタ、Webマニュアル、CHMなどの外部文書を、版・出所・ハッシュ・適用条件付きで管理し、プロジェクトごとに確定した文書集合をAIや開発者へ提供するための構想です。

## 解決したい問題

- 同じ文書の複数の版が混在し、古い版を参照してしまう
- エラッタやWeb文書の更新に気づけない
- プロジェクトによって使用すべき版が違うのに、一律に最新版を使ってしまう
- Web文書を保存しても、いつ・どの範囲を・どう取得したか再確認できない
- AIの回答から、実際に参照した文書の版と位置へ戻れない

DocBOMは、文書の内容の正しさを保証するものではありません。**どの文書の、どの版の、どの実体を使ったかを追跡可能にする**ことを目的とします。

## 基本方針

- 公式配布物を加工せず保存し、ハッシュで特定する
- WebやAPIからの取得物は、公式配布物と区別して不変の取得版として保存する
- 展開HTML、OCR、テキスト、検索索引などは再生成可能な派生物として扱う
- 文書系列、文書の版、ファイル実体、適用対象を分けて管理する
- プロジェクト側で使用文書の版とハッシュをロックする
- 新版の発見と、プロジェクトへの採用を分離する
- AIへはロックされた文書集合だけを渡し、出典位置を返せるようにする

## 既存手法との関係

DocBOMは、Docs as Code、SBOM、技術文書の構成管理、プロベナンス管理、Webアーカイブ、RAGの考え方を接続する構想です。

特にDocs as Codeが主に文書の**作成側**を対象とするのに対し、DocBOMは、ベンダーが発行した異形式の文書を**利用側で取得・選定・固定する**ことを中心にします。

## 現在の状態

構想・設計段階です。まずは小さな縦断プロトタイプで、次を検証します。

1. PDF、Webスナップショット、エラッタを同じ目録で管理できること
2. プロジェクトごとに文書版とハッシュを固定できること
3. 中央の文書リポジトリに新版を追加しても、既存プロジェクトのロックが変わらないこと
4. Web再取得の差分と取得漏れを報告できること
5. 文書ID、版、実体ハッシュ、ページまたは内部パスを出典として返せること

## 想定する構成

```text
DocBOMリポジトリ（このリポジトリ）
  仕様、スキーマ、テンプレート、CLI、架空文書による例とテスト

実際の文書リポジトリ（別リポジトリ）
  PDF、Webスナップショット、CHM、文書目録、検査結果

各利用プロジェクト
  docbom.yaml
  docbom.lock.yaml
```

公開資料であっても再配布可否は個別に確認します。実際のベンダー文書、社内文書、NDA文書は、この公開リポジトリには置きません。公開用の例とテストには、架空または再配布可能な文書を使用します。

## 最初の実装対象

最初はGUI、データベース、本格的なRAG基盤、MCPサーバーを作らず、YAMLと小さなCLIで次を目指します。

```text
init → ingest → validate → resolve → get
```

詳細は[開発ロードマップ](docs/roadmap.md)を参照してください。
