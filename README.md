# DocBOM

**外部技術文書のための構成管理とロックファイル。**

DocBOM（Document Bill of Materials）は、データシート、リファレンスマニュアル、エラッタ、Webマニュアル、Git文書などの外部文書を、版・出所・ハッシュ・適用条件付きで管理し、プロジェクトごとに確定した文書集合をAIや開発者へ提供するためのツールです。

## 解決したい問題

- 同じ文書の複数の版が混在し、古い版を参照してしまう
- エラッタやWeb文書の更新に気づけない
- プロジェクトによって使用すべき版が違うのに、一律に最新版を使ってしまう
- Web文書を保存しても、いつ・どの範囲を・どう取得したか再確認できない
- AIの回答から、実際に参照した文書の版と位置へ戻れない

DocBOMは、文書の内容の正しさを保証するものではありません。**どの文書の、どの版の、どの実体を使ったかを追跡可能にする**ことを目的とします。

## 基本方針

- 公式配布物を加工せず保存し、ハッシュで特定する
- WebやAPIからの取得物は、公式配布物と区別して不変の取得版として保存する
- 展開HTML、OCR、テキスト、検索索引などは再生成可能な派生物として扱う
- 文書系列、文書の版、ファイル実体、適用対象を分けて管理する
- プロジェクト側で使用文書の版とハッシュをロックする
- 新版の発見と、プロジェクトへの採用を分離する
- AIへはロックされた文書集合だけを渡し、出典位置を返せるようにする

## 既存手法との関係

DocBOMは、Docs as Code、SBOM、技術文書の構成管理、プロベナンス管理、Webアーカイブ、RAGの考え方を接続する構想です。

特にDocs as Codeが主に文書の**作成側**を対象とするのに対し、DocBOMは、ベンダーが発行した異形式の文書を**利用側で取得・選定・固定する**ことを中心にします。

## 現在の状態

M1のスキーマ・テンプレート・架空文書セットと、M2の最小CLIを実装しています。

- `init`：文書ストアとプロジェクト設定を初期化
- `ingest`：PDFとGit文書をハッシュアドレスで保存し、Document YAMLを作成・更新
- `validate`：スキーマ、ID、関係先、実体ハッシュ、ロックと目録の一致を検査
- `resolve`：版固定、適用条件、最新Web取得版から `docbom.lock.yaml` を生成
- `get`：ロック済み実体の取得、PDFページ指定、Git文書の行範囲指定による本文抽出

Webの取得・再取得と差分レポートはM3の対象です。M2では既存のWeb取得版を検証・ロックできます。

## 想定する構成

```text
DocBOMリポジトリ（このリポジトリ）
  仕様、スキーマ、テンプレート、CLI、架空文書による例とテスト

実際の文書リポジトリ（別リポジトリ）
  PDF、Webスナップショット、Git文書、文書目録、検査結果

各利用プロジェクト
  docbom.yaml
  docbom.lock.yaml
```

公開資料であっても再配布可否は個別に確認します。実際のベンダー文書、社内文書、NDA文書は、この公開リポジトリには置きません。公開用の例とテストには、架空または再配布可能な文書を使用します。

## 最初の実装対象

初期対応形式は **PDF・Webページ・Git文書** とします。CHMなどの追加形式は後続課題です。

GUI、データベース、本格的なRAG基盤、MCPサーバーは作らず、YAMLと小さなCLIで次の流れを実装しています。

```text
init → ingest → validate → resolve → get
```

詳細は[CLI利用手順](docs/cli.md)と[開発ロードマップ](docs/roadmap.md)を参照してください。
